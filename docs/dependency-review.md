# v0.54.0 Dependency Review

This record covers the dependency changes made for the first published
CPV2/EDEKV2 release, including the consolidated August 2026 Dependabot update.
Both lockfiles were generated by Cargo 1.97.1. All third-party packages resolve
from the crates.io registry and are checksum-bound by the lockfiles; Git and
alternate-registry sources are denied by `deny.toml`.

This is a dependency decision record, not a source-code audit of every
transitive crate. A source scan was used to identify build scripts, procedural
macros, and crates containing `unsafe` tokens. `cargo deny` enforces the
license/source policy and reports duplicates; the two fresh RustSec audits
cover both exact lockfiles.

## Locked transitive refresh

The exact changed package/version set is reviewable in the two lockfile diffs.
The refresh upgrades the SHA-2, Poly1305, Ed25519, Criterion, and AFL families.
It removes the older runtime Poly1305/signature stack, aligns the runtime and
development oracle on the 0.9 Poly1305 family, and adds the 0.11 digest,
`crypto-common 0.2`, `hybrid-array`, `ctutils`, `cmov`, and `rand_core 0.10`
families. Criterion adds `alloca`, `cc`, `find-msvc-tools`, `page_size`, `shlex`,
and target-only `winapi` packages. The fuzz lockfile is regenerated from the same
root dependency declarations rather than left stale. The important review
classes are:

- Changed or newly introduced build scripts are in `alloca`,
  `curve25519-dalek`, and AFL. Existing target and tool crates retain their own
  build scripts. None runs in the publication job.
- `curve25519-dalek-derive` remains the procedural macro in the changed crypto
  family. Existing CLI, serialization, target, and test macros are unchanged;
  they run only in source build or test jobs, never in publication.
- Unsafe-bearing changed families include SHA-2 and Poly1305 optimized backends,
  curve arithmetic, Criterion statistics, AFL instrumentation, `alloca`, and
  `page_size`. No unsafe block is present in this repository's `src/` code. The
  dependency policy does not treat dependency-internal unsafe as reviewed
  application unsafe.
- Licenses encountered are covered by the explicit allow list in `deny.toml`.
  Copyleft is limited to this repository's declared GPL-3.0-or-later license;
  dependencies using an `OR` expression satisfy an allowed alternative.
- The highest declared Rust requirement introduced in the root graph is 1.87
  for a target-specific package and 1.86 for active primary packages. The fuzz
  graph reaches 1.88 through `home`. Both are below Rust 1.97.1. This does not
  create or promise an MSRV.

`cargo deny` intentionally reports duplicate major/minor families instead of
silently allowing them. Current duplicates are the Argon2-side 0.10 digest and
0.1 crypto-common families alongside the Ed25519/Poly1305 0.11 and 0.2 families,
three `rand_core` generations, two `getrandom` generations in the root graph,
and development-only macro families. They are not runtime algorithm negotiation
and do not cross the private crypto boundary. Re-evaluate them on every
dependency change and before release; no advisory or license exception is
recorded.
