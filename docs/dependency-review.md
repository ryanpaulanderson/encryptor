# v0.53.0 Dependency Review

This record covers the dependency changes made for the CPV2/EDEKV2 release.
Both lockfiles were generated by Cargo 1.97.1. All third-party packages resolve
from the crates.io registry and are checksum-bound by the lockfiles; Git and
alternate-registry sources are denied by `deny.toml`.

This is a dependency decision record, not a source-code audit of every
transitive crate. A source scan was used to identify build scripts, procedural
macros, and crates containing `unsafe` tokens. `cargo deny` enforces the
license/source policy and reports duplicates; the two fresh RustSec audits
cover both exact lockfiles.

Existing direct dependencies retained for Argon2id, SHA-512, Poly1305,
password prompting, CLI parsing, properties, temporary test directories, and
benchmarks remain registry packages. Direct `rand`, `hex`, `libc`, `rayon`,
root AFL/libFuzzer packages, `arbitrary`, and `autocfg` were removed. Rayon may
still appear as a Criterion-only transitive development dependency; it is not
used by encryption or decryption.

## Locked transitive refresh

The exact changed package/version set is reviewable in the two lockfile diffs.
The refresh updates the existing CLI, test, platform, serialization, and macro
families and adds the dev-only RustCrypto oracle family. The important review
classes are:

- Build scripts in changed packages: `crossbeam-deque`, `crossbeam-utils`,
  `crunchy`, `getrandom`, `libc`, `proc-macro2`, `quote`, `rayon-core`,
  `rustix`, `rustversion`, `serde`, `serde_core`, `serde_json`, `wasm-bindgen`,
  `wasm-bindgen-shared`, `wit-bindgen`, `zerocopy`, and `zmij`; the fuzz graph
  additionally executes AFL's instrumentation build script. None runs in the
  publication job.
- Changed procedural macros: `clap_derive`, `serde_derive`, `rustversion`,
  `wasm-bindgen-macro`, and `zerocopy-derive`. They run only in source build or
  test jobs, never in the publication job.
- Unsafe-bearing changed families include OS/platform bindings (`rustix`,
  `libc`, `windows-sys`, `getrandom`), optimized parsers/collections and crypto
  internals. No unsafe block is present in this repository's `src/` code. The
  dependency policy does not treat dependency-internal unsafe as reviewed
  application unsafe.
- Licenses encountered are covered by the explicit allow list in `deny.toml`.
  Copyleft is limited to this repository's declared GPL-3.0-or-later license;
  dependencies using an `OR` expression satisfy an allowed alternative.
- The highest declared Rust requirement introduced in the root graph is 1.87
  for a target-specific package and 1.85 for active primary packages. The fuzz
  graph reaches 1.88 through `home`. Both are below Rust 1.97.1. This does not
  create or promise an MSRV.

`cargo deny` intentionally reports duplicate major/minor families instead of
silently allowing them. Current duplicates are caused by the runtime's 0.10
RustCrypto generation, the dev oracle's 0.11 generation, and development-only
CLI/property/benchmark graphs. They are not runtime algorithm negotiation and
do not cross the private crypto boundary. Re-evaluate them on every dependency
change and before release; no advisory or license exception is recorded.

## Required evidence commands

```sh
cargo tree -e features --locked
cargo tree --duplicates --locked
cargo audit --file Cargo.lock --deny warnings
cargo audit --file fuzz/Cargo.lock --deny warnings
cargo deny --manifest-path Cargo.toml --config deny.toml --locked check
cargo deny --manifest-path fuzz/Cargo.toml --config deny.toml --locked check
```
